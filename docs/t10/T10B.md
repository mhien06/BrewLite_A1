# T10B — Hiển: thanh toán không lặp và kho nguyên liệu

## Đọc code theo thứ tự nào?

1. `backend/prisma/schema.prisma`: Ingredient là lượng nguyên liệu, ProductIngredient/ToppingIngredient là định mức; Payment lưu khóa và kết quả.
2. `backend/src/inventory/inventory.service.ts`: tính số phần bán được, cộng nhu cầu của toàn đơn và trừ nguyên liệu.
3. `backend/src/payments/payments.controller.ts`: nhận JWT, body và header Idempotency-Key.
4. `backend/src/payments/payments.service.ts`: kiểm tra khóa, lấy khóa PostgreSQL và xử lý một transaction.
5. `frontend/src/stores/checkout.store.ts`: giữ khóa của lần gửi chưa biết kết quả.
6. `backend/test/t10b.database-test.ts`: các ví dụ thực tế có PostgreSQL, hai service độc lập và rollback.

## Luồng thanh toán

- Tạo PENDING chỉ kiểm tra nguyên liệu, chưa giữ chỗ hoặc trừ kho.
- API lấy đơn thuộc JWT, không lấy số tiền từ frontend.
- Với khóa đã xử lý: cùng tài khoản và cùng orderId/method/simulateSuccess thì trả lại kết quả đã lưu. Khác nội dung trả 409.
- Với lần mới: transaction lấy khóa cho user/key và khóa dòng Order. Đọc lại trạng thái sau khi chờ khóa.
- Thành công: trừ nguyên liệu, chuyển PAID, ghi điểm đúng một lần và lưu Payment. Mọi thao tác cùng transaction.
- Mock thất bại: lưu PAYMENT_FAILED, không trừ kho hoặc cộng điểm. Lần thử lại có kết quả thất bại đã biết dùng khóa mới trên cùng đơn.
- Mất mạng: chưa biết API đã xử lý hay chưa, frontend giữ khóa cũ để gửi lại cùng nội dung.
- PostgreSQL lưu kết quả bền vững. Khóa database bảo vệ cả khi có nhiều instance API; Map trong service chỉ giảm việc tranh chấp trong một instance.
- Gửi khóa mới cho đơn đã PAID hoặc trạng thái không được phép thanh toán trả 409.

## Tồn kho tính từ nguyên liệu

Số phần có thể bán = min(floor(lượng còn / định mức)) của các nguyên liệu bắt buộc.
Ví dụ còn 100g cà phê và 200ml sữa, mỗi phần cần 20g và 30ml: min(5, 6) = 5.
GET /products trả stock tính cho size S, không topping. Đây là ước lượng từng món, không phải giữ chỗ cho cả giỏ.
Backend tính lại toàn bộ nguyên liệu khi tạo đơn và thanh toán, gồm nhiều món dùng chung cà phê/sữa, size và topping.
Khi cập nhật kho: chỉ trừ nếu version còn đúng và stock đủ; tăng version sau cập nhật. Có xung đột thì đọc lại và thử hữu hạn; thiếu kho trả 409, transaction rollback.
Product.stock được giữ để tương thích dữ liệu cũ, không phải nguồn kho chính của ứng dụng thật.
Hủy đơn đang giữ quy tắc state machine của Khoa; chưa bổ sung hoàn tiền/hoàn kho tự động.

## Chạy local

Làm theo README gốc: PostgreSQL → cấu hình backend/.env → migration/seed → backend → frontend.

```powershell
cd backend
npm ci
npm run prisma:deploy
npm run prisma:seed
npm run start:dev
```

Terminal khác:

```powershell
cd frontend
npm ci
npm run dev
```

Không chạy seed để giả lập nhập kho. Seed giữ lượng Ingredient đã tồn tại và chỉ tạo nguyên liệu mặc định khi chưa có; công thức mẫu và khuyến mãi mẫu được cập nhật.

## Chạy test

```powershell
cd backend
npm test
npm run test:e2e
npm run lint
npm run build
```

Test database phải dùng database RIÊNG, tên kết thúc bằng `_test`. Tạo database đó bằng pgAdmin trước; thay user/password/port trong ví dụ.

```powershell
$env:TEST_DATABASE_URL='postgresql://USER:PASSWORD@localhost:5432/brewlite_t10b_test?schema=public'
$env:DATABASE_URL=$env:TEST_DATABASE_URL
npm run prisma:deploy
npm run test:database
Remove-Item Env:TEST_DATABASE_URL
Remove-Item Env:DATABASE_URL
```

Bộ database kiểm tra: hai service cùng khóa; cùng khóa khác payload; thử lại PAYMENT_FAILED; hai khóa khác nhau cho cùng đơn; nhiều đơn tranh nguyên liệu; nhiều món/size/topping dùng chung nguyên liệu; lỗi sau trừ kho rollback toàn bộ. Chỉ xóa bản ghi do test tạo.
Unit/E2E cũ có Prisma mock; không gọi các bài đó là minh chứng concurrency database.

## Demo trên web

1. Đăng nhập, chọn món, size, topping; thêm giỏ rồi checkout.
2. Bấm mô phỏng thất bại: PAYMENT_FAILED, giữ giỏ và kho.
3. Quay lại thanh toán rồi xác nhận: cùng mã đơn, khóa lần mới; thành công chuyển trang xác nhận, có mã đơn và PAID.
4. Mở lịch sử T09 và reload xác nhận; thông tin lấy từ API.
5. Kiểm tra Ingredient stock/version, Payment và LoyaltyTransaction trong pgAdmin.
6. Test tranh kho dùng `npm run test:database` thay vì cố bấm hai tab bằng tay.

Docker dùng hướng dẫn Compose trong README. Sau thay đổi source/migration phải build lại; API tự deploy migration, seed chạy tường minh. Không dùng down -v với dữ liệu cần giữ.

## Thử Idempotency-Key bằng PowerShell

API mặc định là 3001; với bản demo riêng đổi baseUrl thành cổng API được báo khi chạy. Ví dụ dùng tài khoản mẫu do seed tạo.

```powershell
$baseUrl = 'http://localhost:3001'
$login = Invoke-RestMethod -Method Post -Uri "$baseUrl/auth/login" -ContentType 'application/json' -Body (@{email='customer@gmail.com';password='password123'} | ConvertTo-Json)
$headers = @{Authorization="Bearer $($login.accessToken)"}
$products = @(Invoke-RestMethod "$baseUrl/products")
$orderBody = @{items=@(@{productId=$products[0].id;size='S';quantity=1;toppings=@()})} | ConvertTo-Json -Depth 5
$order = Invoke-RestMethod -Method Post -Uri "$baseUrl/orders" -Headers $headers -ContentType 'application/json' -Body $orderBody
```

Lần thứ nhất cố ý thất bại. Gửi lại cùng body và khóa vẫn trả kết quả thất bại đã lưu.

```powershell
$headers['Idempotency-Key'] = [guid]::NewGuid().ToString()
$failedBody = @{orderId=$order.id;method='WALLET';simulateSuccess=$false} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$baseUrl/payments" -Headers $headers -ContentType 'application/json' -Body $failedBody
Invoke-RestMethod -Method Post -Uri "$baseUrl/payments" -Headers $headers -ContentType 'application/json' -Body $failedBody
```

Thử lại thật sự bằng khóa mới, vẫn dùng cùng orderId. Gửi hai lần dưới đây chỉ trừ nguyên liệu và cộng điểm một lần.

```powershell
$headers['Idempotency-Key'] = [guid]::NewGuid().ToString()
$paidBody = @{orderId=$order.id;method='WALLET';simulateSuccess=$true} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$baseUrl/payments" -Headers $headers -ContentType 'application/json' -Body $paidBody
Invoke-RestMethod -Method Post -Uri "$baseUrl/payments" -Headers $headers -ContentType 'application/json' -Body $paidBody
Invoke-RestMethod -Uri "$baseUrl/orders/$($order.id)" -Headers $headers
```

Trong pgAdmin có thể xem các bảng Payment, Ingredient, LoyaltyTransaction và Order. Payment có hai lần thử khác khóa (một thất bại, một thành công); replay không tạo dòng mới. Ingredient thay đổi lượng/version một lần; LoyaltyTransaction có tối đa một dòng cho đơn.
